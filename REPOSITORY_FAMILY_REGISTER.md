## Status meanings
- **CANONICAL** — current source of truth for that product.
- **ACTIVE SIBLING** — separate current product in the same broader family.
- **FAMILY INDEX / UMBRELLA** — family-routing or umbrella repository, not a duplicate runtime.
- **HISTORICAL / REFERENCE** — preserve for provenance/recovery; do not continue ordinary development there.
- **RESERVED** — product name/place reserved, implementation not yet built.
- **PROTECTED** — do not modify through general cleanup.
- **ARCHIVE / REGISTRY** — historical source packs and repository-routing records.

# Account-wide cleanup rules

1. **Canonical first.** New work starts only in a canonical/active sibling repository, never from an old similarly named copy.
2. **Do not merge by name alone.** Similar names are not proof of duplicated product scope.
3. **Preserve unique provenance.** Historical repositories may retain unique source/audit evidence even when not deployable.
4. **Delete runtime duplicates only after blob/reference checks.** Git history remains the recovery path.
5. **No Vercel reintroduction.** Historical Vercel/Netlify files may remain as evidence in archived source, but active direction is GitHub + Cloudflare + Neon.
6. **Revenue Rescue protected.** General cleanup does not modify its application, integrations, database or feature code.
7. **Sensitive/regulated products keep their own gates.** Health, psychology, medication, emergency, child-safeguarding and safety products are not merged simply to reduce repository count.
8. **Repository admin limitations are recorded, not faked.** Default-branch changes, visibility changes, branch protection and repository archive/delete settings must be completed manually when this GitHub connection lacks permission.
