## Governing classification

Every historical name belongs in exactly one of these classes:

1. **CANONICAL PRODUCT** — customer-facing product with its own present source of truth.
2. **FAMILY / UMBRELLA** — parent of configurations and modules.
3. **CONFIGURATION** — sector/customer use of an existing product/core.
4. **SHARED CORE / MODULE** — reusable capability; not another standalone app.
5. **CAPABILITY DONOR / ABSORB** — historical work whose useful capability is retained by a current product.
6. **PLANNED / RECOVERY** — justified product/repository not yet instantiated or still awaiting verified recovery.
7. **INCUBATOR / HOLD** — preserve concept/IP until engineering, legal, safety, clinical or market gates justify build.
8. **CLIENT-SPECIFIC / EXTERNAL SERVICE** — work for a named client; not automatically reusable GENEVIEVE core.
9. **EXCLUDED / NOT ON TRACK-OWNED** — preserve provenance only; do not market as ON TRACK intellectual property.
10. **NON-PRODUCT RECORD** — research, complaints, correspondence, personal logistics or evidence; archive but do not productise.

# 19. PERMANENT RULE FOR FUTURE CLEANUP

Before creating, deleting, renaming or merging any repository/file:
1. search this reconciliation;
2. search `REPOSITORY_FAMILY_REGISTER.md`;
3. search the master portfolio audit / historical registers;
4. classify PRODUCT / FAMILY / CONFIGURATION / SHARED CORE / ABSORB / RECOVERY / HOLD / CLIENT-SPECIFIC / EXCLUDED / NON-PRODUCT;
5. preserve unique provenance;
6. create a new repository only when the boundary is genuinely distinct and justified.

A file can be old without being useless.  
A capability can be valuable without being a new business.  
A new name does not automatically mean a new product.
